# Домашнее задание: свой UI-кит + карточка профиля

Мы разобрали, как типизировать компоненты поверх нативных элементов
(`Button`, `Input`) и как показывать разное в зависимости от состояния.
Теперь то же самое вы делаете сами.

Задание из двух частей:

1. **UI-кит** — три переиспользуемых компонента с нормальной типизацией.
2. **Экран профиля** — маленькое приложение, где эти компоненты применяются,
   с условным рендерингом.

Дизайн не оценивается. Оценивается типизация и то, что компоненты
переиспользуемые.

---

## Подготовка

```bash
npm create vite@latest ui-kit -- --template react-ts
```

```bash
cd ui-kit && npm install
```

Почистите шаблон: `App.tsx` до пустого каркаса, `App.css` до пустого файла.

В `tsconfig.app.json` убедитесь, что стоит `"strict": true` — если нет,
добавьте в блок `compilerOptions`.

Заведите структуру:

```
src/
  ui/          ← переиспользуемые компоненты (не знают о профиле)
  App.tsx      ← экран профиля
```

# Часть 1. UI-кит

## Задача 1. Button

Создайте `src/ui/Button.tsx`.

Требования:

- пропсы **расширяют нативные пропсы кнопки** — компонент должен принимать
  `onClick`, `disabled`, `type` и всё остальное без вашего участия;
- свои пропсы: `variant` (`'primary' | 'secondary' | 'danger'`, по умолчанию
  `'primary'`) и `size` (`'sm' | 'md'`, по умолчанию `'md'`);
- классы вида `btn btn--primary btn--md`;
- `className`, переданный снаружи, должен **добавляться** к своим классам, а не
  затирать их.

Начните с этого:

```tsx
import type { ComponentPropsWithoutRef } from 'react';

interface ButtonProps extends ComponentPropsWithoutRef<'button'> {
  // ваши пропсы
}
```

**Проверьте себя.** Всё это должно компилироваться без единой дописанной
строчки в типе:

```tsx
<Button onClick={() => {}}>Сохранить</Button>
<Button type="submit" disabled>Отправить</Button>
<Button variant="danger" size="sm" aria-label="Удалить">✕</Button>
```

А это — нет:

```tsx
<Button variant="primry">Ошибка в варианте</Button>
```

Если второй пример компилируется — значит, `variant` у вас `string`, а не
объединение литералов. Исправьте.

## Задача 2. Input

Создайте `src/ui/Input.tsx`.

Требования:

- пропсы расширяют нативные пропсы `<input>`;
- свои пропсы: `label: string` (обязательный) и `error?: string`;
- внутри — `<label>` и `<input>`, связанные через `htmlFor` / `id`. Id
  сгенерируйте хуком `useId()`, но разрешите передать свой `id` снаружи:
  `const inputId = id ?? generatedId;`
- если передан `error` — показать текст ошибки под полем, добавить инпуту
  класс-модификатор и атрибут `aria-invalid`;
- `className` склеивается так же, как в кнопке.

**Проверьте себя:**

```tsx
<Input label="Имя" value={name} onChange={(e) => setName(e.target.value)} />
<Input label="Почта" type="email" placeholder="you@mail.com" />
<Input label="Возраст" type="number" error="Только числа" />
<Input value="без подписи" />   // должна быть ошибка: нет label
```

## Задача 3. Textarea

Создайте `src/ui/Textarea.tsx` — то же самое, что `Input`, но поверх
`<textarea>`.

Здесь важно **не копировать код бездумно**: тип элемента другой, поэтому
`ComponentPropsWithoutRef<'textarea'>`, а не `'input'`. Если просто скопируете
файл и поменяете тег — компилятор вам об этом скажет (например, `rows` есть у
textarea, но не у input).

Дополнительный проп: `maxLength` брать нативный, а под полем показывать
счётчик «сейчас/максимум», если `maxLength` передан.

# Часть 2. Экран профиля

В `App.tsx` соберите маленький экран с двумя режимами.

Данные профиля:

```ts
interface Profile {
  name: string;
  email: string;
  about: string;
}
```

## Задача 4. Два режима — условный рендеринг

Состояние:

```tsx
const [profile, setProfile] = useState<Profile>(initialProfile);
const [isEditing, setIsEditing] = useState(false);
```

- **Режим просмотра**: имя, почта, «о себе» обычным текстом + кнопка
  «Редактировать».
- **Режим редактирования**: два `Input` и один `Textarea` + кнопки «Сохранить»
  и «Отмена».

Переключение — через условный рендеринг:

```tsx
{isEditing ? ( ... ) : ( ... )}
```

Важное правило: форма редактирует **копию** данных, а не сам профиль. Заведите
отдельное состояние для полей формы и переносите значения в `profile` только по
кнопке «Сохранить». Иначе «Отмена» работать не будет — проверьте, что она
действительно откатывает изменения.

## Задача 5. Ещё три случая условного рендеринга

1. **Пустое значение.** Если `about` пустой — вместо текста показать
   «Пользователь ничего о себе не написал» (приглушённым цветом).
2. **Ошибка валидации.** Имя не может быть пустым, почта должна содержать `@`.
   При ошибке передавайте текст в проп `error` вашего `Input`, а кнопку
   «Сохранить» делайте `disabled`.
3. **Показывать ошибку не сразу.** Ошибка появляется только после того, как
   пользователь ушёл из поля (`onBlur`) или нажал «Сохранить» — иначе форма
   краснеет ещё до того, как в неё что-то ввели. Заведите для этого состояние
   вида `touched`.

Обратите внимание на разницу двух записей:

```tsx
{error && <span>{error}</span>}        // показать, если есть
{isEditing ? <Form /> : <View />}      // показать одно ИЛИ другое
```

И на грабли: `{count && <p>...</p>}` при `count === 0` отрисует на экране ноль.
Для чисел пишите `{count > 0 && ...}`.

## Задания со звёздочкой (по желанию)

1. **Checkbox.** Сделайте `src/ui/Checkbox.tsx` поверх `<input type="checkbox">`
   с пропсом `label`. Подумайте, какой нативный тип пропсов взять и что делать
   с `type` — его снаружи менять не должны.
2. **Кнопка-ссылка.** Добавьте в кит `LinkButton` поверх `<a>`
   (`ComponentPropsWithoutRef<'a'>`) — выглядит как кнопка, но это ссылка.
   Заметьте, что `href` и `target` вы получите бесплатно, а `disabled` — нет,
   потому что у ссылок его не существует.
3. **Загрузка.** Добавьте `Button` проп `loading?: boolean`: показывать
   «…» вместо содержимого и автоматически ставить `disabled`. Не забудьте, что
   `disabled` может прийти и снаружи — их нужно объединить.
4. **Счётчик символов** в `Textarea` красьте в красный, когда осталось меньше
   10 символов.

## Что проверяем при сдаче

- [ ] `npm run build` проходит без ошибок (это и проверка типов).
- [ ] `Button`, `Input`, `Textarea` расширяют нативные пропсы, а не описывают
      `onClick`/`value`/`onChange` руками.
- [ ] `variant` и `size` — объединения литералов, а не `string`.
- [ ] `label` у `Input` обязательный, `error` — необязательный.
- [ ] `label` и `input` связаны, id сгенерирован через `useId`.
- [ ] Внешний `className` не затирает собственные классы компонента.
- [ ] В папке `ui/` нет ни одного упоминания профиля — компоненты
      переиспользуемые.
- [ ] Нигде нет `any` и `React.FC`.
- [ ] «Отмена» в форме действительно откатывает изменения.
- [ ] Ошибка не показывается, пока пользователь не тронул поле.

## Подсказки

- Забыли синтаксис — смотрите `src/ui/` в проекте «Посты (продвинутый)»,
  там разобраны ровно эти приёмы, и README к нему.
- Если компонент «не принимает onClick» — вы забыли расширить нативные пропсы
  или забыли `{...rest}`.
- Если внешний класс затирает ваш — вы не вынули `className` из `rest`
  деструктуризацией.
- Если в консоли React ругается на неизвестный атрибут `variant` — значит,
  ваш проп уехал на DOM: его нужно вынуть из `rest`.
