
## Что должно получиться

Страница со списком книг:

- форма: поле «Название», поле «Автор», поле «Год» (число) и кнопка «Добавить»;
- под формой — список добавленных книг;
- у каждой книги видно название, автора, год и кнопку «Удалить»;
- если книг нет — надпись «Пока пусто».

Одна книга — это объект вида:

```
id: 3
title: 'Мастер и Маргарита'
author: 'Булгаков'
year: 1967
```

## Шаг 0. Создаём проект

```bash
npm create vite@latest my-books -- --template react-ts
```

```bash
cd my-books && npm install
```

Проверьте, что проект запускается:

```bash
npm run dev
```

## Шаг 1. Чистим шаблон

Vite создаёт демо-страницу со счётчиком — она нам не нужна.

1. В `src/App.tsx` удалите весь код и оставьте пустой каркас:

```tsx
import './App.css';

export default function App() {
  return (
    <main className="app">
      <h1>Мои книги</h1>
    </main>
  );
}
```

2. В `src/App.css` удалите стили шаблона (можно оставить файл пустым — свои
   стили добавите в конце).
3. Удалите `src/assets/react.svg` и импорты картинок, если они где-то остались.
4. `src/main.tsx` и `src/index.css` не трогаем.

Убедитесь, что страница открывается и в консоли нет ошибок.

## Шаг 2. Описываем данные — интерфейс

**Зачем.** Прежде чем писать компоненты, нужно ответить на вопрос: с каким
объектом мы работаем и какие у него поля. Если это описать один раз, TypeScript
будет следить за этим во всём проекте: не даст забыть поле, опечататься в имени
или положить строку туда, где ждали число.

Создайте файл `src/types.ts` и опишите интерфейс `Book` с полями:

- `id` — число;
- `title` — строка;
- `author` — строка;
- `year` — число.

Не забудьте `export`.

Проверьте себя: если написать в `App.tsx`

```ts
const book: Book = { id: 1, title: 'Тест' };
```

редактор должен подчеркнуть ошибку — не хватает `author` и `year`. Убедились —
удалите эту строку.

## Шаг 3. Состояние в App

**Зачем.** Список книг — это данные всего приложения, поэтому они живут в
`App`, а компоненты получают их через пропсы.

В `App.tsx`:

1. Заведите состояние со списком книг. Тип нужно указать явно — из пустого
   массива TypeScript не поймёт, что в нём лежит:

```tsx
const [books, setBooks] = useState<Book[]>([]);
```

2. Для начала положите туда одну книгу вручную (`useState<Book[]>(initialBooks)`),
   чтобы было что выводить на экран.

## Шаг 4. Компонент BookItem — одна книга

**Зачем.** Пропсы — это объект-аргумент функции-компонента. Значит, его тоже
надо описать. Тогда нельзя будет забыть проп или передать не то.

Создайте `src/components/BookItem.tsx`:

1. Опишите интерфейс пропсов:

```tsx
interface BookItemProps {
  book: Book;
  onDelete: (id: number) => void;
}
```

Обратите внимание на `onDelete`: это функция, которая принимает число и ничего
не возвращает (`void`). Так типизируются все колбэки, которые компонент вызывает,
чтобы сообщить наверх о действии пользователя.

2. Напишите компонент, который выводит `<li>` с названием, автором, годом и
   кнопкой «Удалить». По клику вызывайте `onDelete(book.id)`.
3. Не забудьте `import type { Book } from '../types';`

## Шаг 5. Компонент BookList — список

Создайте `src/components/BookList.tsx`:

1. Интерфейс пропсов: `books: Book[]` и тот же `onDelete: (id: number) => void`.
2. Если массив пустой — верните `<p>Пока пусто</p>`.
3. Иначе — `<ul>` и `books.map(...)`, внутри рендерите `BookItem`. Не забудьте
   `key={book.id}`.

Подключите `BookList` в `App` и передайте ему `books`. Удаление пока можно
передать заглушкой — сделаем на шаге 7.

## Шаг 6. Компонент BookForm — форма

Создайте `src/components/BookForm.tsx`:

1. Три состояния: `title`, `author`, `year`. Для строк тип писать не нужно —
   он выводится из `useState('')`.

   С годом подумайте: значение из `input` всегда приходит строкой. Проще всего
   хранить `year` строкой, а превратить в число (`Number(year)`) при отправке.

2. Опишите пропсы. Компонент должен сообщать наверх о новой книге:

```tsx
interface BookFormProps {
  onAdd: (title: string, author: string, year: number) => void;
}
```

3. Обработчик отправки формы — с типом события:

```tsx
function handleSubmit(event: FormEvent<HTMLFormElement>) {
  event.preventDefault();
  // ...
}
```

`FormEvent` импортируется из `react`. А вот в инлайн-обработчиках
`onChange={(event) => ...}` тип писать не нужно — React уже знает, какое это
событие.

4. После добавления очистите поля.
5. Если название пустое — ничего не добавлять.

## Шаг 7. Собираем всё в App

В `App.tsx` напишите две функции и передайте их в компоненты:

```tsx
function addBook(title: string, author: string, year: number) {
  // создать объект типа Book с id: Date.now() и добавить в список
}

function deleteBook(id: number) {
  // отфильтровать список
}
```

Обратите внимание: объявите новую книгу как `const newBook: Book = { ... }` —
тогда TypeScript проверит, что вы не забыли ни одного поля.

Проверьте, что всё работает: книга добавляется, удаляется, при пустом списке
видно «Пока пусто».

## Шаг 8. Стили

Добавьте минимальные стили в `App.css`: список без маркеров, карточка с рамкой,
поля формы в столбик. Дизайн оценивать не будем.

## Что проверяем при сдаче

- [ ] Проект собирается без ошибок: `npm run build` (эта команда запускает
      проверку типов, поэтому ошибок типов быть не должно).
- [ ] Есть файл `src/types.ts` с интерфейсом `Book`.
- [ ] У каждого компонента описан интерфейс пропсов.
- [ ] Колбэки типизированы полностью: `(id: number) => void`, а не `Function`.
- [ ] Нигде нет `any`.
- [ ] Нигде не используется `React.FC`.
- [ ] Типы не продублированы: `Book` описан один раз и импортируется.
- [ ] Там, где тип очевиден (`useState('')`), он не написан вручную.

## Подсказки

- Если не помните синтаксис — смотрите README проекта «Посты», там разобран
  ровно тот же набор тем.
- Красное подчёркивание в редакторе — это не «сломалось», это TypeScript
  говорит, чего не хватает. Прочитайте текст ошибки, обычно там прямо написано
  название пропущенного поля.
- Ошибка вида «Type 'string' is not assignable to type 'number'» означает, что
  где-то не хватает `Number(...)` — скорее всего, это год из формы.
