// USE STRICT
1. Нельзя присвоить значение необъявленной переменной
"use strict";
x = 10; // ReferenceError: x is not defined
Без строгого режима здесь молча создаётся глобальная переменная x, и опечатка в имени превращается в трудноуловимый баг.
2. this в обычной функции равен undefined, а не глобальному объекту
"use strict";
function show() {
  console.log(this);
}
show(); // undefined (без strict - window / globalThis)
Если случайно вызвать метод без объекта, вы сразу получите ошибку, а не будете незаметно портить глобальный объект.
3. Запись в свойства «только для чтения» выбрасывает ошибку
"use strict";
const obj = Object.freeze({ a: 1 });
obj.a = 2;           // TypeError
undefined = 5;       // TypeError
delete Object.prototype; // TypeError
Без строгого режима эти операции молча ничего не делают.
4. Нельзя удалять переменные и функции
"use strict";
let y = 1;
delete y; // SyntaxError
5. Нельзя дублировать имена параметров
"use strict";
function sum(a, a) {} // SyntaxError
6. Запрещены with и восьмеричные литералы вида 010
"use strict";
with (Math) { }   // SyntaxError
let n = 010;      // SyntaxError (нужно 0o10)
7. eval не создаёт переменные во внешней области видимости
"use strict";
eval("var z = 5");
console.log(z); // ReferenceError
8. arguments не связан с параметрами
"use strict";
function f(a) {
  a = 99;
  return arguments[0];
}
f(1); // 1 (без strict - 99)
9. Будущие ключевые слова зарезервированы
implements, interface, package, private, protected, public, static, let, yield нельзя использовать как имена переменных.
Где строгий режим включается сам
В ES-модулях (import/export, файлы .mjs).
Внутри классов (class).
В TypeScript: при "strict": true (а точнее, при входящей в него опции alwaysStrict) компилятор добавляет "use strict"; в начало каждого JS-файла. Поэтому эта строка и появилась в dist/index.js после npm run build.
