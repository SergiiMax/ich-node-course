Микросервисы - это способ строить приложение не как одну большую программу, а как набор небольших независимых сервисов. Каждый сервис отвечает за одну часть бизнес-логики, работает как отдельный процесс, имеет свою базу данных и общается с другими через сеть - обычно по HTTP (REST), gRPC или через очереди сообщений (RabbitMQ, Kafka).
Противоположность - монолит: всё приложение в одном коде, одном процессе и с одной базой.
Пример - интернет-магазин:

Монолит:                        Микросервисы:
┌──────────────────────┐  [Пользователи]       [Каталог]       [Корзина]
│ пользователи         │                │                  │              │
│ каталог              │        ──────┴─────────────┴──────────┴────── сеть / API Gateway
│ корзина              │                          │             │
│ оплата               │                      [Оплата]     [Уведомления]
│ уведомления          │
└──────────────────────┘        у каждого сервиса своя БД
     одна БДПлюсы:

каждый сервис можно разрабатывать, деплоить и обновлять отдельно, не трогая остальные;
масштабировать можно только нагруженную часть (например, запустить 10 копий каталога и одну копию оплаты);
падение одного сервиса не обязательно роняет всё приложение;
разные команды могут работать над своими сервисами и даже на разных языках.
Минусы:

сложнее инфраструктура: нужны Docker, Kubernetes, мониторинг, логирование, API Gateway;
сетевые вызовы медленнее и могут сбоить - нужно обрабатывать таймауты и повторы;
сложно держать данные согласованными между разными базами (нет одной общей транзакции);
отлаживать ошибку, которая проходит через 5 сервисов, намного труднее.
Когда использовать: большие проекты, много команд, разные части системы с разной нагрузкой. Для небольшого проекта или стартапа обычно лучше начать с монолита, а на микросервисы переходить, когда монолит реально начнёт мешать. Частая ошибка - это делать микросервисы «потому что модно» и получить всю сложность без выгоды.
В мире Node.js микросервисы часто пишут на Express или Fastify, а для более структурированного подхода есть фреймворк NestJS со встроенной поддержкой микросервисов.
